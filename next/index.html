If your Bastion sits in a Connectivity landing zone

This is the case the application was written for. A Cloud Adoption Framework estate puts one Bastion in the Connectivity landing zone and joins everything through a Virtual WAN hub. Microsoft supports that topology, with a condition attached: Bastion cannot sit in the hub itself, and connections have to be made by IP address.

What Microsoft's guidance saysWhat that means when you connect
Bastion cannot be deployed inside a Virtual WAN hubIt lives in a spoke, and reaches other spokes through the hub
The IP-based connection feature must be enabledYou reach the machine by private IP address, not by picking it from a list
Standard or Premium SKU is requiredBasic and Developer cannot do this at all
Users need the Reader role on the Bastion resource and its virtual networkAccess is granted on the central Bastion, not on each spoke

So the supported route is connection by IP address. In the portal that means finding the private address yourself, typing it in, and working in a browser tab.

The application removes the lookup. It reads your virtual machines from Azure Resource Graph, which is not bound by the network topology, so you pick the machine by name from any landing zone and it resolves the address for you. The session opens in your own remote desktop client.

Sources: Cloud Adoption Framework, virtual machine remote access and Connect to a VM via a specified private IP address.
