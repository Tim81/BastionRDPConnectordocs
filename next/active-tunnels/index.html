Active tunnels

Every Tunnel connection you open, from either the IP address tab or the Azure VM tab, shows up here for as long as it stays open. RD Gateway connections do not appear on this tab, because they do not open a local port to track.

The Active tunnels tab

Each row names the target, the local port it is listening on, and how long it has been open.

Control Action
Refresh Reloads the list of open tunnels.
Connect RDP Re-launches your remote desktop client against this tunnel’s local port. Useful if you closed the RDP window without stopping the tunnel.
Stop Closes the WebSocket connection to Bastion and ends the tunnel.
Stop ends the session

Stopping a tunnel immediately drops any RDP session using it. Save your work in the remote session first.

Reconnecting

If the WebSocket connection to Bastion drops, for example from a brief network interruption or Bastion maintenance, the tunnel reconnects on its own. It retries up to five times, with a widening gap between attempts. Your RDP session usually stays connected through a reconnect this short, so you may not notice it happened.

If all five attempts fail, the tunnel stops and the system tray shows an error notification. From there, open the Azure VM tab or the IP address tab again and reconnect manually.
